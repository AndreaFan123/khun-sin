# docs structure

| Folder | Contents |
|--------|----------|
| [product](product/) | Vision, requirements, roadmap, user research (e.g. project notes, report-system requirements) |
| [research](research/) | Source-grounded research notes on stranding data, marine conservation law and related evidence |
| [development](development/) | Architecture decision records (ADRs), technical specs, dev environment and deployment notes |
| [testing](testing/) | Test strategy, acceptance checklists (e.g. Lighthouse baseline, RWD checks) |
| [design](design/) | Design tokens, visual and interaction guidelines, data-viz styling |

Naming convention: ADRs are numbered sequentially (`ADR-001-*.md`, `ADR-002-*.md`, …) with status recorded inside each file (Proposed / Accepted / Deprecated / Superseded).

## Research resources

- [Marine conservation API licensing and commercialization](research/marine-conservation-api-licensing-and-commercialization.md) contains the source-level licensing analysis for a free or paid integrated data API, including commercial blockers and a recommended product model.
- [Global marine conservation data resources](research/global-marine-conservation-data-resources.md) is a registry of global biodiversity, protected-area, habitat, conservation-status and stranding sources, with access constraints and possible project uses.
- [Marine conservation frameworks: US, Europe and Taiwan](research/marine-conservation-frameworks-us-eu-taiwan.md) compares mechanisms, laws and reporting processes.
- [Stranding data availability across countries](research/stranding-data-availability.md) documents record-level availability, licences and field-loss findings.

## Operational prototypes

- [International cetacean and sea turtle content pipeline](../content-pipeline/README.md) contains a source registry, a candidate inbox, three unpublished bilingual sample packages, performance placeholders and a repeatable rights-aware validation gate.
